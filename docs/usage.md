# Story usage

The usage extension records newly observed Pi main-agent responses, auxiliary usage entries, compaction/branch-summary usage when provided, and independent permission-reviewer requests. The launcher supplies `WOOD_PI_STORY_ID`; a plain launch is unbound. Branch names never establish a usage binding or a Wood lifecycle claim. Each Pi session retains its original Story association; attempting to reuse a saved session under another Story fails to unavailable.

Records live under `wood-usage/` in the explicit private `PI_CODING_AGENT_DIR`, outside the working repository. The directory is 0700 and session files are 0600. Writes replace one session file atomically. Reads reject symlinks, nonregular files, permissive modes, malformed schemas and oversized records. Limits are 10,000 rows/8 MiB per session and 1,000 sessions per report; exceeding them reports unavailable instead of silently truncating. Records contain IDs, provider/model identifiers, numeric usage, context percentage, timestamps and code-owned provenance categories. They contain no prompts, commands, outputs, child transcript paths or credentials.

Main, subagent and reviewer rows are separate. Main usage includes input, output, cache-read, cache-write and reported total tokens; reasoning tokens are already part of output and are never added again. Context percentage, estimated tokens and window size are session observations bound to the current model/provider, not additive usage. Main model/provider identity comes from the response, including responses preceding a model change. Compaction and branch-summary records without model identity retain unavailable provider/model and price. Reviewer failures/timeouts and zero-filled failed/aborted provider responses create unknown usage records; nonzero partial usage is preserved. Deterministic permission decisions do not call a reviewer or add a reviewer usage row.

After an agent settles, the extension requests the pinned `pi-subagents` v1 read-only `cost` RPC, with a 1.5-second reply bound. It never spawns a child. Only child usage is consumed; the RPC's parent and overall totals are ignored to prevent double charging main-agent usage. Each child's cumulative snapshot replaces its previous observation using the package's run/session identity. Prior observations remain retained across session tree navigation. Unresolved async children or an unsupported/malformed/missing response mark child coverage incomplete. Refresh again after async work completes by finishing another agent turn. There is no polling.

Detached children marked by the pinned package's `PI_SUBAGENT_CHILD=1` do not register a second ambient recorder. Foreground children do not load ambient extensions. The parent RPC remains the sole source for child usage, preventing the same child from also being charged as a main-agent session. Child provider/model attribution remains unavailable through that API.

The cost RPC does not expose provider, model or pricing provenance for its child rows. Those fields remain unavailable; its numeric cost is retained as `reportedCostUsd`, with `costUsd: null`. For main/reviewer usage, nonzero model registry rates establish a Pi estimate (`pricing: pi-model-registry-estimate`); reported cost is preserved rather than recomputed. Missing prices, malformed numbers and all-zero custom/OAuth price definitions remain unknown. Estimates do not establish a provider bill or subscription charge. A total with unknown records is null and separately exposes its known subtotal and unknown-record count.

Usage recording starts when the extension activates. Imported, forked or existing transcript entries are excluded at activation, avoiding attribution of another session's history. Saved rows survive reloads without replay or double counting. Calls lost before persistence or never reported by a provider cannot be reconstructed. Reports always declare `coverage: observed-events-only` and `complete: false`; observed totals are not a full billing reconciliation. A Story with no recorded sessions is unavailable, with null totals. The current session footer uses the same aggregation and formatting as the report's `sessions[].footer`. `+unknown` denotes missing token records or child coverage; `unknown($… known)` retains the known estimated cost subtotal.

Use `/wood-usage-report` to view the current Story's local JSON, or `/wood-usage-report 538` for an explicit Story. It opens a local editor view; editing/dismissing that copy does not modify saved telemetry or inject it into model context. For reproducible JSON, including Stories whose execution has completed, run from the pi-config checkout:

```sh
node --import tsx scripts/usage-report.ts --agent-dir /absolute/private/pi-home --story 538
```

The report includes session observations, the exact footer strings, per-role and per-provider rollups, known subtotals and unknown counts. Report generation reads local files only. Neither capture, reports nor footer rendering queries a provider or launches a model. The footer's existing redraw timer only renders cached state.

The pinned Pi APIs expose no supported five-hour/weekly quota endpoint. No quota is inferred from tokens, subscription assumptions, credential internals or costs. Without an authoritative provider observation, both quota fields remain unavailable. The existing footer observation contract accepts explicit provider-matching quota observations with source, revision and expiry; an external producer remains responsible for supported provider authority. This Story installs no quota producer and makes no claim of live quota availability.

This work is limited to the MacBook configuration. It does not install or migrate a live runtime directory, change Wood Tools, authorize child execution, publish a release or deploy anything. Wood remains the lifecycle/evidence authority; the usage report is local accounting and is not a completion record.
